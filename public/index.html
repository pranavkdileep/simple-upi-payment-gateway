Developer notes

Main API calls and webhook flow

A compact reference for the endpoints, the webhook-style email verification flow, and the secret used to protect sensitive routes.

Core API calls

  • POST /api/create-order creates a new payment request for an amount.
  • GET /api/order/:id checks the current status of one order.
  • POST /api/timeout-orders marks waiting orders older than 10 minutes as timeout.
  • POST /api/test-webhook sends a test webhook event.

Webhook and secrets

The worker listens for Slice payment emails, extracts the payment details, and matches the transaction to the oldest waiting order with the same amount. Protected API routes expect Authorization: Bearer <api_secret>, and the KV namespace stores api_secret, upi_id, webhook_url, and webhook_secret.

Cloudflare setup

Two bindings you need in Cloudflare

These are the two runtime pieces the worker needs before the API, dashboard, and payment checks can work together.

1. D1 database

Bind the production D1 database as prod_d1_db_slice_upi_gateway so orders, payments, and logs can be stored and queried.

2. KV namespace

Bind sclice_upi_gateway_namespace and save the runtime config keys used by the worker and dashboard.

If you want automatic payment email ingestion, also enable Cloudflare email routing or the Worker email trigger for the inbox that receives Slice notifications.

Working

How the flow works end to end

A step-by-step guide from setup to live payment verification, written so the whole flow is easy to scan and hand off to your team.

1

Buy a domain and link to Cloudflare

Start with a branded domain for your gateway, then add it to Cloudflare DNS so you can route traffic securely through the worker and keep TLS, proxying, and hostname management in one place.

2

Create an email route to the Worker in Cloudflare

Set up Cloudflare Email Routing or a Worker email trigger so Slice payment notifications arrive at your worker automatically. That is what lets the gateway inspect incoming messages without a manual inbox process.

3

Create a Slice UPI account and link that email

Open the Slice UPI account you want to receive payments on, then connect the notification email that will receive transaction alerts. The worker relies on those emails to read payer details, amounts, and timing.

4

Create a Cloudflare Worker and D1 database in Cloudflare

Deploy the worker that handles API calls, email parsing, and webhook dispatch, then attach a D1 database so orders, payments, and status changes can be stored reliably and shown in the dashboard.

5

Integrate it to your apps

Use the create-order endpoint in your checkout or app, listen for webhook updates, and refresh order status from your frontend, bot, or backend so payments move from pending to success automatically.
